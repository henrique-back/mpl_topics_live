# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A living review of the microplastics literature, re-run weekly with new papers and published as a static website (`site/`, GitHub Pages) for a wide public and policy audience. It is a fork of the paper's code, `henrique-back/mpl_topics` (git remote `paper`), which keeps the published version: don't push to it. SCOPUS abstracts are topic-modelled with BERTopic, and each paper is assigned an ocean basin via named-entity recognition. The pipeline is a set of Python scripts in `pipeline/`, run in order. There is no build, lint or test suite. Intermediate data, the fitted models, the topic taxonomy and the site's data are all committed. Open reproducibility gaps are tracked in `KNOWN_ISSUES.md`.

## Running

- Environment: `.venv/` (Python 3.12) with pinned `requirements.txt`, which also installs spaCy's `en_core_web_trf` from a wheel URL. Use `.venv/bin/python`, since the system Python has no packages. Python 3.12+ is required (numpy 2.5). Keep **pandas < 3** and **matplotlib < 3.9**; the pipeline is only tested with those. UMAP and HDBSCAN run on the CPU; seeded UMAP is single-threaded, so `consensus.py` and `evaluate.py` run seeds in parallel with joblib.
- Run a step with `.venv/bin/python pipeline/<step>.py` from any folder. The scripts import their siblings by plain name (`import config`), so run them as files, not with `python -m`. Don't name a script after a library it imports (e.g. no `pipeline/bertopic.py`).
- All paths are built in `pipeline/config.py` from the repository root (`config.ROOT`), so they work on Windows, Linux and macOS. Add new paths there or as `config.<DIR> / 'name'`; no hard-coded or absolute paths.
- Secrets live in the gitignored `configurations.ini` at the repository root (template: `configurations.ini.example`), read through `config.read_secrets()`. The GeoNames username is in its `[geonames]` section. Never write it into code.
- Scripts overwrite committed outputs. To test without that, run them on a scratch clone of the repo (`git clone . <scratch>` and copy `pipeline/` and `configurations.ini` into it), then compare with `git diff`.
- AI-written text (`labels.py`, `newsletter.py`) goes through `ai.ask()`, which runs the `claude` CLI headless (`claude -p --model config.CLAUDE_MODEL --json-schema … --tools ""`, own system prompt, in a temporary folder so no CLAUDE.md is loaded): it uses the machine's Claude Code login, no API key. Each call takes one to a few minutes.
- Cost of each step: `analysis.py` takes about 2.5 minutes, `labels.py` about 5 minutes when a whole version needs naming (three Claude calls), `newsletter.py` 1-2 minutes, `layout.py` 20 s for a new version (seconds otherwise), `export_site.py` seconds, `baseline.py` several minutes (`CONSENSUS_RUNS` UMAP fits, in parallel), `assign.py` and `basin_map.py` seconds; `evaluate.py sizes` seconds, `umap` and `search` hours (~75 UMAP fits, ~1,400 HDBSCAN fits; cached in `bertopic/evaluation/cache/`, keyed on the papers, encoder and UMAP parameters), `consensus` an hour or more (30–40 UMAP fits, mostly cached by `search`, and three linkages per candidate). `refresh_citations.py` makes ~200 Scopus requests (a few minutes, longer when rate-limited). Encoding every paper (1-2.5 h for 20k with Qwen3-Embedding-4B on an Apple M5 Pro; a weekly batch takes about a minute) and the `extract` and `geocode` stages of `ner.py` are slow or call external APIs.

## Pipeline (run order and data flow)

Weekly order: `fetch_scopus` → `embeddings` → `ner` → `assign` → `basin_map` → (`refresh_citations`, first Monday of the month) → `analysis` → `labels` → `layout` → `newsletter` → `export_site`. **`pipeline/weekly.py`** runs them as subprocesses (log in `logs/weekly-<date>.log`, gitignored), then `git add get_data NER bertopic graphs site`, commits and pushes; on a failed step it commits nothing and shows a macOS notification (`osascript`); a re-baseline flag in `runs.csv` only notifies. `--dry-run`, `--from <step>`. launchd starts it Mondays 06:00 (`scheduling/br.ufba.mpl-weekly.plist`, a template with `__REPO__`/`__HOME__`; install command in README). Every per-paper file is keyed on **`paper_id`** (`config.paper_ids()`: lower-cased stripped DOI, or `eid:<EID>` for the one paper without a DOI), and each incremental step processes only the ids it lacks.

1. **`pipeline/fetch_scopus.py`** (weekly): runs `config.SCOPUS_QUERY` on the Scopus Search API (COMPLETE view, cursor paging; `[scopus] api_key`/`insttoken` in `configurations.ini`), restricted to `ORIG-LOAD-DATE AFT` the date in `get_data/scopus_last_fetch.txt` minus 7 days (`--since YYYYMMDD` overrides). Entries are mapped to the export's columns (`to_row`), cleaned with `clean_data.clean()`, and those whose EID (`config.eids`, parsed from `Link`) or `paper_id` is already present, or with no DOI, are dropped; the rest are **appended** to **`get_data/alldata.csv`**, the master dataset (~20k papers; columns include `Abstract`, `Year`, `Cited by`, `DOI`, `Title`, `Authors`, `Link`), and their citation counts to **`get_data/citations.csv`** (`paper_id, cited_by, retrieved_on`; `config.load_citations()`), dated today, and `paper_id, added_on` (today) to **`get_data/added.csv`** (`config.ADDED`; no rows for papers from before the record), which defines the newsletter's week. Nothing is written unless the whole search was retrieved.
   - `pipeline/refresh_citations.py` (monthly, and after a full rebuild): looks up every paper by EID in batches of 100 (`EID(…) OR …`, STANDARD view) and rewrites `citations.csv` with today's counts. Papers Scopus doesn't return keep their row; papers with none take alldata's `Cited by`, dated `config.reference_date()` (`--offline` does only that). `alldata.csv`'s `Cited by` is the count when first fetched and is not used by the analyses.
   - `pipeline/clean_data.py` is the full-rebuild path: it cleans a complete export (`get_data/scopus_data.csv`, not committed), dropping duplicate DOIs (including all but one paper with a missing DOI), missing or empty abstracts and "Corrigendum" titles, and overwrites `alldata.csv`.
   - `clean()` also normalizes every abstract (`normalize_abstract`): it removes the publisher's copyright statement ("© 2022 Elsevier Ltd." and variants; ~99% of export abstracts have one, API abstracts almost never) and the API's `<sup>`/`<inf>` tags (the export has plain text), so both sources are encoded and modelled alike. The abstracts in `alldata.csv` are already normalized.
2. **`pipeline/embeddings.py`**: encodes with `config.EMBEDDING_MODEL` (Qwen3-Embedding-4B, with the instruction `EMBEDDING_PROMPT`, truncated to `EMBEDDING_DIM` = 1024 and L2-normalized) the papers whose `paper_id` is not in **`bertopic/preprocessed_data/embeddings.npz`** (arrays `paper_id`, `embeddings` as float16, `encoder`; read with `config.load_embeddings(ids)`, which returns float32 rows in the order of `ids`). If the encoder settings (`config.encoder()`) differ from the saved ones, it re-encodes every paper; the taxonomy then needs a re-baseline.
3. **`pipeline/ner.py`** (needs only `alldata.csv`). Stages `extract` → `geocode` → `manual`; `--from <stage>` starts later:
   - `extract`: spaCy `en_core_web_trf` extracts GPE/LOC entities of the papers with no row in `data_loc.csv` (first column `paper_id`, then the locations in order of first mention; read with `keep_default_na=False, na_values=['']` so names like "NA" survive) and appends never-seen names to `all_locations.csv` (whose committed order is not first-mention order and which contains an "NA" absent from `data_loc.csv`, so it is appended to, never rebuilt).
   - `geocode`: the GeoNames API geocodes only names in neither `fuzzy_location_data.csv` (found) nor `fuzzy_error_locations.csv` (not found) nor `ERROR_DICT` (`geocode()` tries exact, fuzzy, then per-word fuzzy). A `status` reply (credit limit, bad user) raises `GeoNamesError` and stops the run; network errors skip the name. Neither is recorded, so the next run retries it. Progress is saved every 25 names and on exit; new rows have no basin yet, so `assign_basins` computes only theirs.
   - `manual` (offline): `ERROR_DICT` overrides or adds coordinates by hand and clears those locations' basins. A haversine BallTree snaps each location to the nearest cell of a 1° ocean-basin grid (`range_area.csv`, codes named in `range_basin_list.csv`). **Only locations with no basin yet are computed**: exact ties are broken differently across scikit-learn versions, and a full recompute moves ~50 papers. Each paper takes the majority-vote basin of its geocoded locations (unresolved names are NaN and don't vote), and coastal and open-ocean codes are merged (`MERGE_CLASSES`).
   - Outputs: **`NER/merged_fuzzy_classes_labels.csv`** (columns `paper_id`, ..., `Basin`) and `NER/maps/range_area_counts.csv`.
4. **`pipeline/assign.py`** (weekly): papers without a topic get one from the current taxonomy (see below): the base model's `transform` (from v2, a consensus model: `consensus.ConsensusCluster.predict`, a plurality vote (`consensus.vote`) of the `CONSENSUS_KNN` nearest fitted papers in the embedding space, outliers voting as -1; v1 uses its fitted UMAP + HDBSCAN `approximate_predict`), then, for papers still at -1, each addition's model in order. Appends a row to `bertopic/taxonomy/runs.csv` and flags a re-baseline when the unmatched share of predicted papers exceeds the version's `expected_unmatched` (`params.json`, the leave-one-out vote of the fitted papers) by more than `config.REBASELINE_POOL_SHARE`. A no-op when there are no new papers.
5. **`pipeline/basin_map.py`**: world choropleth of papers per basin, saved to `graphs/map.{svg,png}`. Colorbar ticks are derived from the counts. The SVG has no date and stable element ids, so it only changes when the map does.
6. **`pipeline/analysis.py`**: the per-paper and per-topic tables of the current taxonomy (no figures; the site draws them). Settings in `config.py`: `MIN_CITATION_AGE`, `MIN_GINI_PAPERS`, `MIN_CELL_PAPERS`, `GINI_LEVEL`.
   - Citations: `citation_rates()` reads `citations.csv`; citations per year = `cited_by / age`, age = `retrieved_on` − (Year + 0.5) in years, NaN for papers younger than `MIN_CITATION_AGE`, which every citation analysis leaves out. `gini()` is bias-corrected by n/(n−1) (NaN for n < 2 or no citations); `gini.csv` keeps every topic × year cell (at `GINI_LEVEL`) with `Papers`, and the site shows only cells with ≥ `MIN_GINI_PAPERS`. Charts over time stop at `config.last_full_year()` (the year before the last fetch, `scopus_last_fetch.txt`).
   - Loads the current base pickle and calls `update_topics(docs, topics=<assignments>, vectorizer_model=topic_model.vectorizer_model)`, then rebuilds centroid topic embeddings with `_create_topic_vectors(documents, embeddings)` (update_topics doesn't for added topics) and representative docs with `_save_representative_docs`. Labels come from `taxonomy.labels()`.
   - Writes CSVs to `bertopic/preprocessed_data/`: `docs_topics.csv` (one row per paper with `paper_id`, topic at each level of `TOPIC_LEVELS`, basin, year, citations, age and rate), `id.csv`, `rep_docs.csv` (`paper_id`/DOI/title), `topic_frequency.csv`, `freq.csv`, `topics_over_time.csv` (fine topics, all years), `gini.csv`. The `.svg`/`.html` files left in `graphs/` (except `map.*`) are hand exports for the paper, not produced by code.
7. **`pipeline/labels.py`**: Claude names and describes (≤ 6-word label, 1–2 sentence description, for the public) every topic of the current major version without a row in **`bertopic/taxonomy/v<N>/labels.csv`** (`level, topic, label, description, keywords, label_source=ai, model, labelled_on`), one call per level, bottom-up (fine, mid, coarse), from each topic's top 10 c-TF-IDF words at its level (refit like `baseline.level_labels`), its 5 papers closest to the centroid and its subtopics' labels. A no-op until a new version or addition; `--level`, `--redo`. `taxonomy.labels()` uses these labels (falling back to the keyword labels of `topics.csv` / `hierarchy.parent_label`), so every output does.
8. **`pipeline/layout.py`**: the 2-D layout of the site's paper map, **`bertopic/models/v<N>/layout.csv`** (`paper_id, x, y, method`). Fitted once per major version (seeded UMAP, `min_dist=0.25` so topics don't collapse to a point) on the fitted papers; new papers are placed at the mean position of their `CONSENSUS_KNN` nearest fitted papers and appended, so points never move within a version. Created lazily (the first weekly run after a baseline).
9. **`pipeline/newsletter.py`**: the issue of the latest `added_on` date of `added.csv` (one per date; `--redo` rewrites it): papers grouped by coarse topic, a section per topic with ≥ `NEWSLETTER_MIN_SECTION` papers, the rest (and outliers) in "also"; one Claude call with titles, journals, DOIs and abstracts, a word budget per section (`TARGET_WORDS` ≈ 1000), at most ~2 DOI links per section and 8 per issue; links to DOIs outside the week's papers are stripped (`keep_known_links`). Writes `site/data/newsletter/<date>.json` and rebuilds `index.json`.
10. **`pipeline/export_site.py`**: the site's data in `site/data/` (`meta.json`, `taxonomy.json`, `levels/{coarse,mid,fine}.json`, `basins.json`, `map.json`, `geo/{basins,land}.geojson`): aggregates only, plus the map's anonymous points (x, y, fine topic). Basins are renamed for display (`BASIN_DISPLAY`; "Unknown" → "No basin"); the basin polygons are the 1° grid of `ner.py` (gaps filled by nearest cell, `MERGE_CLASSES` applied) dissolved per basin. Reuses `analysis.citation_rates`/`gini` and `taxonomy.level_topics`.

**Website** (`site/`: `index.html`, `app.js`, `style.css`; no build step, ECharts 5.6.0 from jsDelivr): tabs *This week* (newsletter + archive), *Explore* (level switch + sunburst + topic select; the selected topic is highlighted, never a colour per topic, in every chart; deep links `#explore/<level>/<topic>`), *Methods* (text in `index.html`, numbers from `meta.json`). Colours are CSS tokens with light/dark themes (dataviz skill palette: one accent, grey context, one-hue sequential ramp). Test locally with `.venv/bin/python -m http.server -d site`. `.github/workflows/pages.yml` publishes `site/` on pushes to `main` that touch it.

Occasional steps, around the **taxonomy** (`pipeline/taxonomy.py` documents the files):
- **`pipeline/evaluate.py <stage>`** (before a re-baseline): chooses the parameters, writing to `bertopic/evaluation/`. Stages in order: `sizes` (precision of each analysis against topic size → set `config.TOPIC_LEVELS`, `MIN_GINI_PAPERS`), `umap` (neighbourhood preservation and seed stability; suggests the most seed-stable setting within 5% of the best kNN recall → set `config.UMAP_PARAMS`), `search` (HDBSCAN grid on that UMAP over 10 seeds and held-out folds: noise-penalized DBCV via `relative_validity_`, NPMI/diversity, stability across seeds, held-out assignment, author-keyword information), `report` (Pareto front of single fits), `consensus` (the consensus baseline.py fits, for the Pareto candidates or `--configs`: topics, outliers and split-half agreement per `CONSENSUS_THRESHOLDS`, leave-one-out vote per `CONSENSUS_KNNS`; `--converge` adds agreement against runs per half → set `config.HDBSCAN_PARAMS` and `CONSENSUS_*`, record the choice in `bertopic/evaluation/CHOICE.md`). Values are hand-set in `config.py`; `--sample N --quick` for checks.
- **`pipeline/baseline.py`**: fits the consensus topic model on all papers (`consensus.py`: `CONSENSUS_RUNS` seeded UMAP + HDBSCAN fits, co-association, average linkage (`tree`) cut at `CONSENSUS_THRESHOLD` (`cut`), groups under `min_cluster_size` → -1) and opens a new major version `v<N>.0`: `bertopic/models/v<N>/base.pkl` (+ `params.json` with the encoder, split-half agreement (`consensus.agreement`: ARI, AMI on both-clustered papers, outlier kappa, best-match Jaccard), outlier share, leave-one-out vote (`loo_kept`, `expected_unmatched`), package versions and git commit; `consensus.csv` with each paper's confidence), `bertopic/taxonomy/v<N>/{topics,assignments}.csv` with keyword labels (the next weekly run names the topics with `labels.py` and fits the new `layout.csv`), `hierarchy.csv` (fine topics merged smallest-first into the most similar, by mean-centred centroids, until each level of `TOPIC_LEVELS` meets its minimum size; levels are nested) and `merges.csv` (each merge and its similarity), and `crosswalk.csv` / `crosswalk_counts.csv` from the previous major version, matched by paper overlap (Jaccard, Hungarian; pairs under `MIN_JACCARD` = 0.1 are not matches; `old_split_into` / `new_merged_from` count topics sharing ≥ 20%). v1's crosswalk came from the paper's `bertopic/model`. Run for the first model and when a re-baseline is flagged; never automatically.
- **`pipeline/discover.py`**: fits a model on the pool of unmatched papers and adds clusters whose centroid similarity to every topic is below `config.NOVELTY_MAX_SIMILARITY` as topics of a minor version `v<N>.<k>`. Its model is saved as `addition_<k>.pkl`; pool papers in accepted clusters move into the new topics (`moved_in`). **Not usable yet**: `pool_ids()` is a stub and the thresholds are None until the session on unmatched papers.

## Invariants to keep in mind

- **Key on `paper_id`, never on row order.** Join per-paper files on `paper_id`; `alldata.csv` stays append-only (the weekly steps only add papers), but no file depends on its row order.
- **Past assignments never change within a major version.** `assign.py` only adds rows; `discover.py` only moves unmatched (-1) papers into newly added topics, and records `moved_in`. `first_topic`, `method` and `version` keep how each paper was first assigned. Older major versions (`taxonomy/v<N>/`, `models/v<N>/`) are frozen.
- **Embeddings carry their encoder.** `config.load_embeddings` raises unless `embeddings.npz` was made by the expected encoder (`config.encoder()`, or for a consensus model the encoder recorded at its fit), so a model never mixes embedding spaces.
- **Pickled models load only under the pinned `requirements.txt`.** `taxonomy.save_model` strips the embedding model and fitted c-TF-IDF (analysis.py refits it) and compresses, keeping `base.pkl` under GitHub's 100 MB limit (v1, with UMAP: ~78 MB for 12k papers; a consensus model stores only paper ids and topics and reads the embeddings from `embeddings.npz`). Get topic labels before saving.
- **A single fit can't be reproduced** (UMAP differs across seeds, machines and versions; a refit of the paper's configuration gave ARI 0.54). That is why the baseline is a consensus over many seeds (its split-half ARI is in `params.json`) and topics change only through `baseline.py` or `discover.py`, with versions. `bertopic/model` is the paper's model, kept only for the v1 crosswalk: don't modify it.
- **Citations are dated per paper.** Never compute ages from a fixed year: each count in `citations.csv` has its `retrieved_on`, and the time plots end at `config.last_full_year()`, derived from the last fetch.
